# KOL Scoring Model

一个可解释、可调权、可复算的达人（KOL / KOC / 买手）筛选与分层模型。

> 脱敏自真实品牌达人投放项目。**不含任何真实达人信息、平台后台数据或公司投放策略**；仓库内 `data/sample_kols.csv` 为完全合成的样例数据，仅用于演示打分逻辑。

---

## 解决的问题

达人投放最常见的两种失败：

1. **凭感觉选人**——看粉丝量和近期数据，忽略「粉丝画像与目标人群是否重合」。10w 粉的号投出去零转化，往往不是内容差，是人不匹配。
2. **无法解释为什么选他**——投放复盘时说不清「为什么选这 20 个不选那 20 个」，下次换个执行的人，标准就全变了。

这个模型把筛选从「经验判断」变成「可复算的分数 + 分层 + 对应动作」。

---

## 四个维度

| 维度 | 权重 | 回答的问题 | 数据来源 |
|---|---|---|---|
| D1 账号匹配度 | 30 | 他的粉丝，是不是我要的人 | 粉丝画像、垂类分布、地域 |
| D2 内容质量 | 25 | 他的内容，稳不稳定 | 近 30 天发布、互动、爆文率 |
| D3 历史转化 | 30 | 他带得动货吗 | 曝光、进店 UV、成交、转化率 |
| D4 合作成本 | 15 | 值不值 | 报价、CPM、报价/GMV 比 |

**为什么转化权重最高**：投放的最终目的是成交，不是曝光。曝光好看但转化差的号，是最贵的那种便宜。

**为什么成本只占 15%**：成本是筛选条件，不是决策依据。先用成本闸门过滤，再用前三维排序。

详见 [`model/kol-scoring-model.md`](model/kol-scoring-model.md)。

## 分层与对应动作

| 分层 | 分数区间 | 建议动作 |
|---|---|---|
| S | ≥ 80 | 优先排期，可谈长期 / 年框 |
| A | 65–79 | 正常投放，观察 2 轮后升级 |
| B | 50–64 | 小额测试，验证转化再放量 |
| C | < 50 | 不投；若成本极低可做铺量 |

分层不是终点，**动作才是**。同一分层里，D1 高但 D3 低的号要「换内容角度再试」，D3 高但 D4 差的号要「谈价」——这是模型比排序表多出来的一层。

## 快速开始

```bash
git clone <repo-url>
cd kol-scoring-model

# 用样例数据跑一遍
python src/score.py --input data/sample_kols.csv

# 自定义权重
python src/score.py --input data/sample_kols.csv --config model/scoring-config.json
```

输出 `output/scored_kols.csv`，含各维度得分、总分、分层、建议动作。

无第三方依赖，只用标准库。

## 设计取舍

### 1. 用分位数归一化，不用绝对阈值
不同品类、不同平台的绝对数值差异巨大（美妆 CPM 和家居 CPM 不是一个量级）。模型内部统一转成**同批次内的分位数**，只比较「这批人里谁更好」，不跨批次比较绝对值。

代价：不能跨批次横向对比历史分数。解法是保留原始值，需要时按批次重算。

### 2. 硬闸门 + 软打分两层
先过硬闸门（粉丝量区间、近 30 天是否活跃、有无违规记录），再进打分。
**闸门不参与加权**，避免「一个维度极高把不合格的号拉上来」。

### 3. 权重可配置，但要有理由
`model/scoring-config.json` 里所有权重可改。但每次改都要在 `reports/` 里记一条：为什么改、改完投放结果如何。
没有记录的调权，等于没有模型。

### 4. 不做「预测 GMV」
只做相对排序，不做绝对预测。样本量不足时，任何 GMV 预测都是伪精度。

## 已知局限

1. **依赖后台数据质量**。平台数据口径变化会直接影响 D3，需要定期校准。
2. **新号无法评估**。历史数据不足的号，D2/D3 会失真，建议单独走「新号测试池」。
3. **不覆盖内容创意质量**。一个匹配度高、数据好的号，仍可能因为 brief 写得差而投崩——模型管选人，不管内容。
4. **分位数归一化的批次依赖**。批次人数少于 15 时，排序不稳定。
